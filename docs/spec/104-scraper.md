# 104 人力銀行職缺撈取工具 (104 Job Bank Scraper) — 技術規格與開發文檔

本技術文檔旨在詳細說明基於 Python 開發的 **104 人力銀行職缺撈取工具**（`fetch_104_jobs.py`）之系統架構、核心技術實作、資料欄位字典（Data Dictionary）以及多功能使用指南。

此工具專為要求精準、高效且具備容錯力（Robustness）的求職者或資料分析師設計，免除透過瀏覽器手動複製職缺的繁瑣過程，實現自動化批量職缺檢索、智慧清洗與多格式（CSV/JSON）資料落庫。

---

## 1. 系統架構與工作流程

該工具是一個單晶片自持式（Self-contained）腳本，採用模組化設計。核心解析邏輯拆分為多個獨立的純函式（`_normalize_url`、`_extract_job_id`、`_extract_tag_descriptions`、`_extract_skill_descriptions`），並將地區解析（`resolve_area`）、關鍵字拆分（`parse_keywords`）與終端截斷顯示（`truncate_display`）等共用邏輯統一收斂，消除 CLI 模式與互動模式之間的程式碼重複。其高層級工作流程如下圖所示：

```mermaid
graph TD
    A[使用者啟動腳本] --> B{判斷模式}
    B -->|無參數| C[啟動互動式引導 GUI/CLI]
    B -->|有參數| D[解析命令列參數 CLI Args]
    
    C --> E[設定搜尋條件: 關鍵字/縣市/頁數/性質]
    D --> E
    
    E --> F[對應縣市為 104 地區代碼 Area Code]
    F --> G[開始批量關鍵字迭代]
    
    G --> H[發送模擬 HTTP GET 請求]
    H --> I{API 回傳狀態碼}
    I -->|200 OK| J[解析 JSON 資料與 Metadata]
    I -->|其他錯誤| K[記錄錯誤日誌並中斷此分頁]
    
    J --> L[提取下一頁分頁資訊]
    J --> M[根據 jobNo 執行記憶體級資料去重]
    
    M --> N{是否達到最大頁碼或無新資料?}
    N -->|否| O[隨機延遲 1~2 秒] --> H
    N -->|是| P{是否還有下一個關鍵字?}
    
    P -->|是| Q[安全保護延遲 2.0~3.5 秒] --> G
    P -->|否| R_Detail[遍歷職缺並調用詳細 API 獲取完整工作內容 (含微延遲)]
    R_Detail --> R[進行資料清洗與核心欄位格式化]
    
    R --> S[寫入帶有 BOM 的 UTF-8 CSV]
    R --> T[寫入標準 UTF-8 JSON]
    R --> U[生成終端機美觀預覽表格]
```

## 2. 核心技術實作細節

### 2.1 必要請求標頭 (Required Headers)
104 的 API 會對缺少必要 HTTP 標頭的請求直接返回 `403 Forbidden`，因此腳本在請求時統一帶入 `DEFAULT_HEADERS`：
* **`User-Agent`**：設定為一般瀏覽器的 User-Agent 字串；缺少此標頭時 API 會回 403。
* **`Referer`**：設定為 `https://www.104.com.tw/jobs/search/`。此標頭表示請求來自搜尋頁；缺少時 API 會回 403。
* **`Accept-Language`**：宣告偏好繁體中文 (`zh-TW`)，確保回傳內容為繁體中文。

### 2.2 縣市對應與地區代碼解析 (Area Code Mapping)
104 的後端 API 對地區進行了精細的數字化編碼。例如，`台北市` 的內部代碼為 `6001001000`。為降低使用者使用的難度，腳本透過共用函式 `resolve_area()` 實作了**雙向比對器**，CLI 模式與互動模式共用同一套解析邏輯：
* 內建全台 22 個主要縣市的代碼字典。
* 支援**精準匹配**（輸入 `台北市`）與**模糊匹配**（輸入 `台北` 或 `臺北`），自動過濾掉多餘字元並定位到正確的 104 地區代碼。
* 若使用者未輸入地區，則預設不帶入 `area` 參數，自動擴展至「全台灣地區」。

### 2.3 批量關鍵字迭代與記憶體去重 (Batch Deduplication)
當使用者輸入多個關鍵字（如 `Python, Django, FastAPI`）時，腳本會將其視為一組獨立的搜尋任務。
* **記憶體級雜湊表去重**：腳本內建 `seen_job_nos` 集合。在抓取過程中，無論是在同個關鍵字的不同分頁，還是不同關鍵字之間，都會檢查 `jobNo`（職缺代碼）。
* 如果發現相同的 `jobNo`，則將其從結果集中濾除，保證輸出的資料表中**每一筆職缺皆為唯一**。

### 2.4 請求頻率限制 (Rate Limiting Strategy)
為了避免對 104 伺服器造成負擔，腳本設計了雙層延遲：
1. **分頁間隨機延遲**：每抓完一頁，線程會隨機睡眠 `1.0 ~ 2.0` 秒。
2. **任務間安全延遲**：當結束一個關鍵字搜尋，準備啟動下一個關鍵字時，線程會隨機睡眠 `2.0 ~ 3.5` 秒。
> [!NOTE]
> 延遲採隨機區間而非固定時間，讓請求平均分散，避免在短時間內集中送出。

### 2.5 Excel 中文相容性優化 (UTF-8 BOM Encoding)
若直接將中文字串以標準 `UTF-8` 編碼寫入 CSV 檔案，微軟的 Microsoft Excel 在 Windows/macOS 系統下開啟時，常會因為缺乏位元組順序記號而將其誤判為其他編碼，導致**中文變成亂碼**。
* **解決方案**：本腳本在寫入 CSV 時，指定編碼為 `utf-8-sig`。這會在 CSV 檔案的開頭插入不可見的 BOM 標頭（`\xef\xbb\xbf`），明確指示 Excel 使用 UTF-8 解碼，實現**開箱即用的中文完美顯示**。

### 2.6 完整工作內容動態獲取 (Full Description Fetching)
由於 104 搜尋 API 提供的 `description` 欄位僅為關鍵字高亮的**預覽片段/摘要**，為了解決工作描述被截斷的問題，腳本設計了二次請求機制：
* **ID 解析提取**：透過 `_extract_job_id()` 函式從列表返回的職缺 URL（例如 `//www.104.com.tw/job/8s12x`）中解析提取出 base36 `job_id` （`8s12x`）。
* **URL 正規化**：透過 `_normalize_url()` 函式將 104 回傳的 protocol-relative URL（`//www.104.com.tw/...`）自動轉換為完整 HTTPS URL。
* **同步詳情獲取**：對每一筆去重後的職缺發送 GET 請求至詳細內容 API `https://www.104.com.tw/job/ajax/content/{job_id}`，並帶上對應職缺頁面作為 `Referer` 標頭（詳情 API 要求 Referer 為該職缺頁面，否則拒絕請求）。
* **微隨機延遲保護**：每次詳情請求前隨機延遲 `0.1 ~ 0.3` 秒，控制請求頻率，避免瞬間送出大量請求。
* **保持原始資料**：若特定職缺之詳細 API 請求超時、出錯或返回無效資料，對應的「工作內容」與「薪資待遇」欄位將直接設為 `null`，不進行任何 fallback 或資料腦補，確保資料的真實性與一致性。

## 3. 資料欄位對應字典 (Data Dictionary)

腳本在接收到 104 後端的原始 JSON 回傳後，會自動將其高度嵌套、簡寫的欄位進行結構化提取與中文化映射。欄位規格如下表所示：

| 匯出欄位名稱 | 原始 JSON 鍵值                      | 資料型態 | 欄位說明與清洗規則                                                     |
| :----------- | :---------------------------------- | :------- | :--------------------------------------------------------------------- |
| **職缺代碼** | `jobNo`                             | String   | 104 系統中的唯一識別碼，用於資料去重。                                 |
| **職缺名稱** | `jobName`                           | String   | 職缺職稱（移除多餘的 HTML Tags）。                                     |
| **公司名稱** | `custName`                          | String   | 徵才企業之法定註冊或對外顯示名稱。                                     |
| **產業類別** | `coIndustryDesc`                    | String   | 該公司所属行業（如：電腦系統整合服務業）。                             |
| **地區**     | `jobAddrNoDesc` + `jobAddress`      | String   | 合併縣市行政區與街道地址（如：台北市大安區 忠孝東路..）。              |
| **薪資待遇** | `jobDetail.salary` (透過 ajax/content 動態獲取) | String / null | 透過詳細資料 API 獲取原始薪資描述字串（如「月薪60,000~70,000元」或「待遇面議」），若詳細 API 獲取失敗則為 `null`。 |
| **薪資下限** | `salaryLow`                         | Integer / null | 薪資範疇的最低金額，直接保留 API 原始值（「待遇面議」時 104 API 回傳 `0`），缺失時為 `null`。 |
| **薪資上限** | `salaryHigh`                        | Integer / null | 薪資範疇的最高金額，直接保留 API 原始值（面議時回傳 `0`，無上限時回傳大於 9999999 的數值），缺失時為 `null`。 |
| **更新日期** | `appearDate`                        | String   | 將 `YYYYMMDD` 格式清洗為標準 ISO `YYYY-MM-DD` 格式。                   |
| **應徵人數** | `applyCnt`                          | Integer  | 當前該職缺累計的投遞人數。                                             |
| **工作內容** | `jobDetail.jobDescription` (透過 ajax/content 動態獲取) | String / null | 透過詳細資料 API 獲取完整工作描述，若詳細 API 獲取失敗則為 `null`，不進行任何 fallback。 |
| **電腦專長** | `pcSkills`                          | String   | 從嵌套列表中提取技能 `description` 並用逗號合併（如：`Python, Git`）。 |
| **科系要求** | `major`                             | String   | 限制科系（用逗號合併，如：`資訊工程相關, 數理統計相關`）。             |
| **特色標籤** | `tags`                              | String   | 提取特色福利標籤（如：`外商公司`、`週休二日`、`距捷運站210公尺`）。    |
| **職缺連結** | `link.job`                          | String   | 職缺詳細頁面的直接跳轉 URL。                                           |
| **公司連結** | `link.cust`                         | String   | 104 公司介紹頁面的直接跳轉 URL。                                       |

## 4. 使用指南與執行範例

### 4.1 部署前置條件
本工具僅依賴輕量級的 HTTP 請求庫 `requests`，已列在專案的 `pyproject.toml` 中。以 uv 同步依賴即可：
```bash
uv sync
```

### 4.2 執行指令詳解

#### 互動模式（推薦新手使用）
執行後，腳本會一步步引導您完成條件配置，即便不具備程式背景也能輕鬆上手：
```bash
uv run 104/fetch_104_jobs.py
```

#### 進階命令列（CLI）模式
您可以利用腳本提供的豐富選項，整合進您個人的自動化 Pipeline 中：
```bash
uv run 104/fetch_104_jobs.py --keyword "關鍵字1,關鍵字2" --pages 頁數 --area "縣市名稱" --type 性質代碼
```

* **參數參數說明**：
  * `-k`, `--keyword`：搜尋關鍵字。多個關鍵字請用逗號（半形 `,` 或全形 `，` 皆可）分隔。
  * `-p`, `--pages`：每個關鍵字要撈取的頁數。每頁固定回傳 30 筆，預設值為 `3` 頁。
  * `-a`, `--area`：求職縣市（如 `台北市`、`新竹市`）。若不填代表全台灣。
  * `-t`, `--type`：職缺性質。`0` 代表全部工作（預設值），`1` 代表全職，`2` 代表兼職或工讀。

### 4.3 輸出位置
`jobs_104_<關鍵字>_<timestamp>.csv` 與 `.json` 寫在專案根目錄的 `output/104/`（由 `OUTPUT_DIR` 常數定義，以腳本位置推算，不受當前工作目錄影響；資料夾不存在時會自動建立）。`output/` 已列入 `.gitignore`，不進版本控制。

## 5. 異常處理與防禦性設計

為了確保腳本在大規模或不穩定網路環境下仍能穩定運行，內建了以下防禦性設計：
1. **超時中斷保護 (Timeout Protection)**：每次對 104 發起的請求（包含搜尋與詳細資料 API）皆設定 `timeout` 限制，防止因對方伺服器響應過慢或卡死導致程式無限期掛起。
2. **無損鍵值提取 (Key-Error Protection)**：所有欄位皆透過 `.get()` 方式安全提取。即使 104 調整了後端 JSON 的某些鍵值，腳本也能確保程式不會因 `KeyError` 崩潰，缺失欄位會以 `null` 表示，不自行腦補預設值。
3. **優雅退出 (Graceful Shutdown)**：支援 `Ctrl + C`（鍵盤中斷指令），在使用者手動取消時，程式會捕捉 `KeyboardInterrupt` 異常，安全完成收尾並乾淨退出，不殘留系統線程。
4. **詳情請求頻率控制 (Ajax Micro-Delay)**：由於抓取完整描述需要額外發送 HTTP GET 請求，腳本在詳情獲取時實作了 `0.1 ~ 0.3` 秒隨機微延遲。若詳情 API 請求失敗，對應欄位直接設為 `null`，確保資料真實性。
