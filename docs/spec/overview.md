# 專案總覽 — 求職雷達 (Job Search Agent)

## 產品概念

過濾出符合自我發展方向的職缺，避免花大量精力在海量求職平台中人工篩選；同時了解不同產業、公司的發展方向。

## 核心技術（目標藍圖）

README.md 定義了五項核心技術。這裡標註各項的實作現況——**目前只有第 2 項落地**，其餘尚未動工：

| # | 核心技術 | 說明 | 現況 |
| :-- | :--- | :--- | :--- |
| 1 | 工作評分邏輯 | 設計工作評分方法與提示詞 | ❌ 未實作 |
| 2 | 從求職平台獲取職缺資訊 | 擷取職缺並轉為結構化資料，供 AI 分析 | ✅ 104 平台已實作，見 [104-scraper.md](104-scraper.md) |
| 3 | 擷取公司資訊與評價 | 擷取公司相關資訊並結構化 | ❌ 未實作 |
| 4 | AI 分析工作流 | 依評分邏輯給職缺打分並給出簡短評語 | ❌ 未實作 |
| 5 | 趨勢與興趣分佈分析 | 從全台／全球角度分析職缺趨勢 | ❌ 未實作 |

規劃新功能時，先把它對應回上表的分類。

## 目前的程式碼地圖

```
main.py                  uv 產生的樣板，尚未成為真正的進入點
104/fetch_104_jobs.py    104 職缺爬蟲（單檔自足腳本，無 package 結構）
104/jobs_104_AI_*.csv    範例輸出（手動歸檔）
docs/spec/               設計文件
```

尚無 package 結構、測試框架與 lint 設定。第一個要長出來的模組會決定整體佈局，屆時再定架構。

## 資料流（現況）

```
104 搜尋 API ──┐
              ├─→ parse_jobs() ─→ 中文鍵名的職缺 dict ─→ CSV (utf-8-sig) + JSON
104 詳情 API ──┘
```

職缺 dict 使用**中文鍵名**（`職缺代碼`、`職缺名稱`、`工作內容`…），欄位定義見 [104-scraper.md](104-scraper.md) 第 3 節。未來的 AI 分析層應以此結構為輸入契約，並容忍其中的 `null`（詳情 API 失敗時的真實表現）。
