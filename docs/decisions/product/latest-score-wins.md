# 多筆評分以最新的一筆為準

## 決策背景與問題

同一筆職缺可以有多筆評分紀錄：每次重評都新增一筆，不覆寫（見 [job-auto-scoring §10](../../product/features/job-auto-scoring.md#10-追蹤同一筆職缺的評分變化history)）。職缺表的分數、排序、篩選與展開列的目前的評分，每筆職缺只能用一筆代表的評分，問題是要用哪一筆。

## 考慮過的替代方案

- 有手動評分時用手動評分，沒有時才用最新的自動評分：
  - 這是更早採用的做法，不再採用。
  - 查詢多一層判斷。使用者手動評分之後又重評，查詢仍然看到舊的手動評分，看不出重評的結果。
  - 之後手動評分整個拿掉（見[決策紀錄：評分功能的邊界](score-feature-boundary.md)），這個方案也就沒有適用的情況。

## 最終決策

- 用評分時間最新的一筆；評分時間相同時，用後寫入的一筆。
- 舊的紀錄仍然保留，可以在展開列的所有評分紀錄中切換檢視、比較前後的判斷。
- 詳細規則見 [job-auto-scoring §13.2.3](../../product/features/job-auto-scoring.md#1323-代表的評分)。
