# AI 回應不能用時重打一次

## 決策背景與問題

單筆評分失敗時不寫入，要等使用者再勾選送去評分才會重評（見 [job-auto-scoring §4.2.14](../../product/features/job-auto-scoring.md#4214-評分中與評完)）。問題是：

- 要不要在同一次評分內立即重打？
- 重打哪些失敗、重打幾次？

評分失敗分成兩類：

- AI 呼叫失敗：連不上、服務錯誤、API key 無效、模型不存在等。
  - 呼叫 AI 時已經會自動重試暫時性的連線與服務錯誤，重試幾次仍失敗才算呼叫失敗。
  - 其他錯誤，例如 API key 無效，重打多少次都一樣失敗。
- AI 回應不能用：有回應，但回應是空的，或不通過 [§4.2.9](../../product/features/job-auto-scoring.md#429-ai-回應的檢查) 的檢查（格式不符、分數超出範圍、理由或總評是空白）。
  - AI 每次的輸出不同，偶發的不能用，重打一次多半就正常。
  - 但也可能持續發生，例如使用者改過的提示詞模板讓 AI 一直給錯格式。這時每次重打都多花一次 AI 費用。

## 考慮過的替代方案

- 所有失敗都重打：
  - 暫時性的呼叫失敗已經自動重試過，再重打一輪很少救得回來。
  - API key 無效這類錯誤重打一定失敗，每一筆都要多等一輪。
- 回應不能用時重打 2 次以上：
  - 持續不能用時，一筆的 AI 費用變成三倍以上。
  - 偶發的不能用，重打 1 次通常就夠。
- 不重打：
  - 偶發的格式錯誤也要使用者事後手動勾選重評。
  - 整批評完才看得到失敗，這時要再送一次、再等一次。

## 最終決策

- 只在 AI 回應不能用時立即重打，最多 1 次，一筆最多呼叫 AI 2 次。
- 重打後仍不能用才算失敗，失敗原因用最後一次的。
- AI 呼叫失敗不在評分流程另外重打。
- 送去評分與試跑都適用，兩者走同一套評分流程。
- 影響 [job-auto-scoring](../../product/features/job-auto-scoring.md) 的 `score` 故事與 NFR-cost。
