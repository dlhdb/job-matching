# 0002 評分快取只涵蓋 AI 評分

## 決策背景與問題

評分結果寫入資料庫後，重跑同一批職缺時，沒有變動的職缺不該再付一次 AI 費用。問題是快取要涵蓋評分的哪些部分，以及快取鍵要由哪些東西組成。

## 考慮過的替代方案

- **快取整份評分結果，快取鍵納入整份 `preferences.yaml`**：薪資欄位不會送進提示詞，所以快取鍵裡沒有薪資。職缺改了薪資、快取鍵卻不變，就會沿用舊的薪資分數與總分。另外，只改權重或淘汰條件也會讓快取鍵改變，明明 AI 的輸入沒變，卻重新呼叫 AI。

## 最終決策

- 快取只涵蓋 AI 的三個維度與評語。快取鍵只由送給 AI 的東西組成：供應商、模型、system 與 user 提示詞。
- 硬性淘汰、薪資分數與加權總分每次都重算，沿用時也覆寫整列。
- 詳細設計見 [F1-01 §8.2.1](../features/F1-01-job-scoring.md#821-快取鍵)。
