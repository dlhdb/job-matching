# 產品需求文件（PRD）索引 — 求職雷達

本目錄描述「要做什麼、為什麼、做到什麼程度算完成」；「怎麼做」請看 [docs/spec/](../spec/)。

每個功能各自一份文件，放在 [features/](features/)。實作某功能時，只需讀本索引加上該功能的文件。

## 產品目標

- 過濾出符合自我發展方向的職缺，避免花大量精力在海量求職平台中人工篩選。
- 了解不同產業、公司現在的發展方向。

## 目標使用者

- 求職者本人（專案擁有者）：想快速掌握符合自己方向的職缺，並得到可信的評分與評語。

## 用例

採用 JTBD 的 job story 格式：「**當**（情境），**我想要**（動機），**以便**（預期成果）。」「我想要」只寫動機，不寫解法。

| ID | 當… | 我想要… | 以便… |
| :-- | :--- | :--- | :--- |
| UC-01 | 我想知道市場上有哪些符合自己方向的職缺 | 不必一頁頁翻求職平台，就能掌握所有相關職缺 | 把時間花在判斷，而不是蒐集 |
| UC-02 | 搜尋結果有上百筆職缺 | 快速知道哪些值得細看、為什麼 | 只把心力放在少數真正符合的職缺上 |
| UC-03 | 我對某個職缺感興趣 | 知道這家公司的狀況與外界評價 | 判斷值不值得投遞 |
| UC-04 | 我在規劃接下來的學習與職涯方向 | 知道各產業、公司正往哪裡發展 | 調整自己的學習重點 |
| UC-05 | 我已經看過一段時間的職缺 | 看清自己實際被哪些職缺或產業吸引 | 確認自己真正想要的方向 |

## 非目標

- 不做多使用者服務、帳號系統或對外公開的網站。
- 不自動投遞履歷。
- 不對求職平台做大量、高頻的抓取（頻率限制見各爬蟲規格）。

## 核心技術

每項核心技術都用來滿足上方的用例；所有功能都歸屬於下列其中一項，功能 ID 的第一個數字即為核心技術編號。

| # | 核心技術 | 定義 | 滿足用例 |
| :-- | :--- | :--- | :--- |
| 1 | 工作評分邏輯 | 設計工作評分方法與提示詞。 | UC-02 |
| 2 | 從求職平台獲取職缺資訊 | 從不同求職平台擷取職缺，轉換成結構化資料，供 AI 分析。 | UC-01 |
| 3 | 擷取公司資訊與評價 | 從網路上擷取公司相關資訊與評價，轉換成結構化資料，供 AI 分析。 | UC-03 |
| 4 | AI 分析工作流 | 依工作評分邏輯給職缺與公司打分，並給出簡短評語。 | UC-02、UC-03 |
| 5 | 趨勢與興趣分佈分析 | 從全台、全球角度分析職缺趨勢，並發現自己對職缺或產業的興趣分佈。 | UC-04、UC-05 |

## 撰寫與使用流程

1. **新增功能**：複製 [_template.md](_template.md) 到 `features/`，依命名規則取檔名，並在上表登記，狀態設為 `草稿`。
2. **定稿**：「待決問題」清空後，狀態改為 `待實作`。還有待決問題的 PRD 不要開始實作。
3. **實作**：狀態改為 `實作中`，依「功能需求」實作，不做「範圍外」列出的事。
4. **驗收**：逐條執行「驗收標準」的驗證方式，回報每條結果（✅ / ❌ 與實際輸出）。全部通過才把狀態改為 `✅ 已完成`。
